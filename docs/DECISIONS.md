# 决策记录

每条决策一段话，写明时间、决定和理由。

**2026-11-05 · 从零重建，项目更名 Humpback。** 旧项目 v2 有 7 万行代码，但实盘核心只有 4,209 行；金额全程用 float，LLM 处在开仓决策的热路径上，流程文档远多于运行代码。只保留经过审计确认扎实的思路和代码：v10 测试网订单状态机的思路、Decimal 撮合模型、行情采集模块（第二阶段迁移）。研究、治理、闪电贷合约和多 AI 编排全部封存。

**2026-11-05 · 运行时没有 LLM。** 证据：有研究让 LLM 代理自己反复做回测，一个故意泄漏未来信息的策略仍然通过了 DSR 和 PBO 检验。AI 只提交策略规格卡，代码由 Humpback 实现，并接受统一的验证阶梯。

**2026-11-05 · 不自建钱包。** 采用硬件钱包、交易所代理密钥、自写签名服务的组合。Bybit 2025 年被盗事件中，多签合约本身没有被破解，失守的是签名界面加盲签，所以签名前的检查放在自己的签名服务里做。

**2026-11-05 · 没有原生支持的订单类型在本地直接拒绝。** Hyperliquid 和 Lighter 的"市价单"实际是带价格上限的限价单。Humpback 不替调用方悄悄转换，而是要求调用方明确发送 LIMIT + IOC，并给出价格。

**2026-11-05 · 一次"查不到"不算证据。** Hyperliquid 对实际存在的订单也可能返回 `unknownOid`。要把订单确认为不存在，需要连续多次查询都查不到，并且超过宽限时间。

**2026-11-05 · 单一语言 Python，核心零第三方依赖。** 账本、风控、对账只使用标准库；签名库（eth-account、msgpack）作为可选依赖，只在签名服务里使用。
